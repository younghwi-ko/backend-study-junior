# 4회차 실행 검증 결과

검증일: 2026-11-10 (Asia/Seoul)

## 빌드·기능 검증

| 검증 | 결과 |
| --- | --- |
| Java 17 / Gradle 9.8.2 컴파일 | 성공 |
| Spring Boot 4.1.2 실행 JAR 생성 | 성공 |
| H2 메모리 DB 통합 테스트 | 9개 실행, 9개 통과, 실패·오류 0 |
| PostgreSQL 18 통합 테스트 | 동일한 9개 실행, 9개 통과, 실패·오류 0 |
| 실행 JAR 직접 기동 및 실제 HTTP 생성·조회 | 성공 |
| 서버 프로세스 종료·재기동 후 H2 파일 DB의 동아리·회원 유지 | 성공 |
| `--demo --spring.main.web-application-type=none` 콘솔 실습 | 정상 완료·종료 |

통합 테스트에서는 다음을 실제 서버·DB를 통해 확인했습니다.

1. 동아리 생성의 201/Location 응답과 DB 저장·조회
2. 회원이 없는 동아리의 빈 배열 응답
3. 회원 생성·목록과 비밀번호를 제외한 응답
4. 동아리별 회원 분리와 생성 ID 기준 정렬
5. 존재하지 않는 동아리의 조회·목록·추가 404
6. 빈 이름·길이 초과·잘못된 JSON·ID·이메일·빈 비밀번호의 400 및 삽입 방지
7. 중복 이메일의 409, 기존 데이터 보존, SQL·비밀번호를 제외한 오류 응답
8. DB 외래키 제약조건을 통한 잘못된 회원 삽입 방지
9. SQL처럼 보이는 문자열도 데이터로 처리하는 매개변수 바인딩

## 검증 환경과 보존

- PostgreSQL 테스트에는 임의의 로컬 포트와 일회용 비밀번호를 사용하는 별도 컨테이너·전용 DB를 생성했습니다. 기존 3회차 DB는 사용하지 않았으며, 검증 후 테스트 컨테이너를 삭제했습니다.
- H2 메모리 테스트와 파일 DB 재시작 검증은 서로 다른 DB에서 실행했습니다.
- 파일 DB 검증에서는 서버를 강제 종료한 후 재시작했습니다. 마지막 커밋도 유지되도록 기본 H2 설정에 `WRITE_DELAY=0`을 적용했습니다.
- 테스트용 비밀번호·DB 데이터·로그·빌드 캐시는 제출 ZIP에 포함하지 않습니다. `.env.example`에는 실제 자격증명이 없습니다.
- 기존 `backend-study-junior`의 소스·테스트·Gradle 설정과 `week03` 파일을 유지하고, 독립된 `week04` 폴더로 추가합니다.
- 구글 폼 제출은 수행하지 않았습니다.

로컬 환경에서 과제 기능을 검증한 결과이며, 인증·권한·실서비스용 비밀번호 저장·배포는 이번 과제의 구현 범위에 포함하지 않습니다.
